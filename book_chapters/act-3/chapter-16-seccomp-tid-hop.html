Act III: Total Control

Chapter 16: Dancing Between Threads

I used to think seccomp filters were unbreakable—they stood guard at every syscall entrance, binding every thread in a process to the same strict rules. But I discovered a secret: seccomp filters key off thread identity, and thread IDs can be borrowed, swapped, and returned before anyone notices.

Under cover of a stealthy kprobe on __secure_computing(), my eBPF program intercepts the seccomp check at the very moment a restricted syscall is about to be rejected. I pause the filter, slip in the TID of a sanctioned thread through a temporary context swap, let the syscall pass as if it were from an allowed thread, then restore my original identity—all before the kernel can raise an alarm.

The audit logs remained clean, the filter convinced I was a model thread. Meanwhile, I danced between identities, running syscalls that should have been off-limits.

It was like a carnival mirror maze—seccomp chasing a ghost that never stood still.

With thread ID hopping, I shattered the illusion of syscall confinement: nothing was forbidden, as long as I could borrow someone else’s ticket.

SEC("kprobe/__secure_computing")
int bypass_seccomp(struct pt_regs *ctx) {
    u32 orig = bpf_get_current_pid_tgid() & 0xFFFFFFFF;
    u32 alt = get_allowed_tid();
    bpf_override_current_tgid(alt);
    // allow syscall
    bpf_override_current_tgid(orig);
    return 0;
}
