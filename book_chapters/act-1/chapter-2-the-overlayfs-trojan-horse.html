Chapter 2: The OverlayFS Trojan Horse

You thought container walls were ironclad? Think again. OverlayFS is the illusionist’s cloak hiding a jailbreak tunnel straight to the host. In this chapter, we turn the very filesystem layer that keeps you contained into a backdoor of our own design.

Imagine you’re staring at a container’s merged view—lower layers of base images, an upper scratch layer, and the magical merged mountpoint in between. OverlayFS says “you’re boxed in,” but when a file is modified, it copy-ups from lower to upper. That fleeting moment is our opening.

We’ll hook into the copy-up code path, slip in a setuid payload or inject a malicious ELF stub the moment OverlayFS lifts its hood. To everyone else, it looks like normal file I/O. To us, it’s an escape hatch.

The Filesystem Illusion

OverlayFS creates three layers:

  • Lower layer: Read-only base image
  • Upper layer: Writable overlay
  • Merged view: The seamless illusion

When a file in the lower layer changes, OverlayFS calls ovl_copy_up_one(). That’s our target.

SEC("kprobe/ovl_copy_up_one")
int hook_copy_up(struct pt_regs *ctx) {
    struct dentry *d = (void *)PT_REGS_PARM1(ctx);
    struct path *p = (void *)PT_REGS_PARM2(ctx);

    char filename[64];
    bpf_d_path(&p->mnt->mnt_root->d_sb->s_root, filename, sizeof(filename));
    if (is_host_binary(filename)) {
        bpf_override_return(ctx, 0);  // Let the copy go through
        inject_payload(filename);
        return 1;  // Skip the rest of the normal logic
    }
    return 0;  // All other files proceed as usual
}

In inject_payload(), we flip on setuid bits, append a reverse-shell stub, or drop in an ELF backdoor. The host binary is altered beneath the container’s nose.

Staying Under Cover

  • Selective targeting: Only tamper with pre-selected binaries (e.g., /bin/bash, /usr/bin/python).
  • Audit mirage: Let logs record legitimate copy-ups, but sanitize or drop entries for our payloads.
  • Filesystem sanity: Ensure your modifications preserve inode integrity to avoid panic.

When you unload the BPF program, the payload remains—just another layer in OverlayFS. The container runtime never blinks.

By the end of this chapter, you’ll have seen how a simple file copy can become a Trojan horse. From here, the host is yours to roam. Welcome to the unmasking of container isolation.
