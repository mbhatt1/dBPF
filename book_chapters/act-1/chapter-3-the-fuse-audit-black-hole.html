Chapter 3: The FUSE Audit Black-Hole

I used to think logs were sacred. Sysadmins worship the audit subsystem like oracles: they promise evidence of every syscall, every file access, every secret exfiltrated. But when I discovered FUSE hooks, I realized I could feed that oracle an empty page.

Enter FUSE: the user-space filesystem magic that streams every I/O event through your own code. What if you could convince those events to vanish into thin air? Imagine opening /etc/shadow, pulling every hash, and watching the audit logs still sing praises: “all clean, nothing suspicious.”

The trick is simple and diabolical. FUSE mounts implement file operations callbacks in userspace. I write a tiny eBPF program that spoofs a FUSE mountpoint and intercepts audit events destined for the real audit buffer, diverting them into my dummy filesystem sinkhole. The kernel thinks it’s writing logs; I think of them as confetti in the wind.

With the audit black hole in place, defenders see compliance, dashboards stay green, and incident responders chase shadows. Meanwhile, I roam through sensitive directories, leaving not a footprint.

Creating the Abyss

  1. Hook audit_log_start() at the kernel entry point.
  2. Filter events based on my target criteria: user IDs, file paths, event types.
  3. Redirect approved events to /dev/null via my FUSE mount.
  4. Let the rest flow as usual so the audit subsystem never notices missing entries.

My evidence destroyer lives in the shadow of the audit system. It’s a silent assassin, swallowing singeing logs before they ever reach the disk.

By the end of this chapter, you’ll hold the power to breach invisibility itself. The security team will never know you were there.
