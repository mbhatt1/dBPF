Act II: Kernel Intrusion

Chapter 13: The Ultimate Trust Violation

I used to believe that module signing was the unbreakable seal guarding the kernel’s integrity. The idea that only cryptographically signed code could run with kernel privileges felt like a moat no attacker could cross.

But module loading in Linux is just more code, and code can be intercepted. Under cover of a stealthy kprobe, I hooked into module_sig_check(), the very function that validates signatures.

As the kernel read the signature blob, my eBPF program diverted it to a BPF map and served up a legitimate signature stored in memory. Once the check completed, I swapped the verified buffer for my own malicious driver.

The kernel nodded and loaded my code without a second thought. To the security team, logs gleamed with successful signature verifications; to me, the backdoor was wide open.

With this ultimate trust violation, I had proven that even cryptographic defenses can be subverted. Act II may be drawing to a close, but the most dramatic scenes are yet to come.
