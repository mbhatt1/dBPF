The FUSE Audit Black‑Hole

February 02, 2025

The FUSE Audit Black-Hole: Evading Security Monitoring

Wut

Redirecting kernel audit buffers into a dummy FUSE mount so SELinux and auditd never record the attacker’s tracks. This technique allows attackers to perform malicious actions without leaving evidence in security logs, creating a “black hole” for audit events.

graph TD
    A[Kernel Audit Event] -->|1. Generated| B[Audit Buffer]
    B -->|2. Intercept| C[eBPF Program]
    C -->|3. Redirect| D[Dummy FUSE Mount]
    D -->|4. Discard| F[/dev/null]
    B -->|5. Miss| E[SELinux/Auditd]
    G[Attacker Actions] -->|6. No Logs| H[Stealth Operations]

Why

Because eBPF + misconfiguration => broken isolation. Audit logs are a critical security control for detecting and investigating security incidents. By intercepting audit events before they reach monitoring systems like SELinux and auditd, attackers can operate with significantly reduced risk of detection, effectively blinding security monitoring tools.

Attacker hat on

  1. Identify a target system with eBPF capabilities and audit logging
  2. Create a dummy FUSE filesystem mount point
  3. Develop an eBPF program that hooks into the kernel’s audit subsystem
  4. Load the malicious BPF program with appropriate privileges
  5. Configure the program to redirect specific audit events to the FUSE mount
  6. Perform malicious actions without leaving audit trails
  7. Establish persistence for both the FUSE mount and eBPF program

Defender hat on

  1. Remove CAP_BPF from untrusted processes and containers
  2. Implement BPF LSM policies to restrict eBPF program loading
  3. Monitor for unexpected FUSE mounts and eBPF programs
  4. Use multiple, independent audit collection mechanisms
  5. Implement integrity monitoring for the audit subsystem
  6. Consider using eBPF-based security tools that can detect malicious eBPF usage

Conclusion

eBPF is all you need. The ability to intercept and redirect kernel audit events through eBPF provides attackers with powerful primitives to evade security monitoring. This technique highlights the importance of treating eBPF capabilities as privileged operations that should be tightly controlled, especially in environments where audit logging is a critical security control.

Technical Details

Audit Subsystem Architecture

The Linux audit subsystem consists of:

  • Kernel components that generate audit events
  • Audit buffers that temporarily store events
  • Userspace tools like auditd that collect and process events
  • Security frameworks like SELinux that use audit events for enforcement

Audit events flow from the kernel through buffers to userspace collectors, providing visibility into security-relevant actions on the system.

Exploitation Technique

The exploit leverages eBPF’s ability to attach to kernel functions that handle audit events. By intercepting these calls, an attacker can:

  1. Hook audit generation: Attach to functions like audit_log_start() or audit_filter_rule()
  2. Identify sensitive events: Filter for specific events that might reveal attacker activity
  3. Redirect selected events: Send targeted events to a dummy FUSE filesystem
  4. Preserve normal operation: Allow non-sensitive events to flow normally

FUSE Component

The Filesystem in Userspace (FUSE) component acts as a “black hole” for audit events:

  • Creates a userspace-controlled filesystem mount
  • Implements minimal handlers that discard received data
  • Appears as a valid destination for kernel operations
  • Leaves no trace of the redirected audit events

Detection Methods

Defenders should monitor for:

  • Unexpected eBPF programs attaching to audit-related functions
  • Discrepancies between expected audit events and actual logged events
  • Unusual FUSE mounts, especially those with minimal implementation
  • Gaps in audit logs during periods of system activity
  • Changes to audit configuration or routing

This technique demonstrates why proper eBPF restrictions are critical for maintaining the integrity of security monitoring systems, especially in environments where audit logging is a key security control.
