NetNS VLAN Ghost: Invisible Cross-Namespace Network Tunneling

Wut

A technique using eBPF to create hidden communication channels between isolated network namespaces by manipulating VLAN tag handling. This attack bypasses network namespace isolation by intercepting and modifying network packets at the driver level, allowing containers and processes to communicate across security boundaries without detection by standard monitoring tools.

Why

Because eBPF + misconfiguration => broken isolation. Network namespaces are a fundamental isolation mechanism in container environments, preventing unauthorized communication between containers. By using eBPF to manipulate VLAN tags and packet handling at the driver level, attackers can create covert channels that bypass these isolation mechanisms while remaining invisible to standard monitoring tools.

Defender hat on

  2. Implement BPF LSM policies to restrict eBPF program loading
  3. Monitor for unexpected eBPF programs attached to network functions
  4. Use network monitoring at multiple levels, including physical interfaces
  5. Implement egress filtering and anomaly detection
  6. Consider using eBPF-based security tools that can detect malicious eBPF usage

Conclusion

eBPF is all you need. The ability to manipulate network packet processing through eBPF creates a dangerous scenario where container isolation can be completely bypassed while appearing intact. This technique highlights why eBPF capabilities should be treated as highly privileged operations that require strict access controls, especially in multi-tenant environments.

Technical Details

Network Namespace Architecture

Linux network namespaces provide isolation for network resources:

  • Network interfaces: Each namespace has its own set of interfaces
  • Routing tables: Separate routing configuration per namespace
  • Firewall rules: Independent firewall rules for each namespace
  • Socket information: Isolated network statistics and information

VLAN (Virtual LAN) tagging is used to segment network traffic on shared physical interfaces, with the kernel handling the addition and removal of VLAN tags.

Exploitation Technique

The exploit leverages eBPF’s ability to attach to kernel functions that process network packets. By intercepting these calls, an attacker can:

  1. Hook packet processing: Attach to functions like __netif_receive_skb_core() and dev_queue_xmit()
  2. Identify target packets: Filter for packets from specific namespaces or containers
  3. Manipulate VLAN tags: Add, modify, or strip VLAN tags to create covert channels
  4. Bypass namespace boundaries: Redirect packets across namespace boundaries
  5. Evade detection: Ensure monitoring tools see only expected traffic patterns

Detection Methods

Defenders should monitor for:

  • Unexpected eBPF programs attached to network-related functions
  • Discrepancies in network traffic between different monitoring points
  • Unusual VLAN tag patterns or modifications
  • Unexpected cross-namespace communication
  • Traffic that appears on physical interfaces but not in namespace monitoring

This technique demonstrates why proper eBPF restrictions are critical for maintaining network isolation, especially in environments where network segmentation is a key security control.

Real-world Impact

In practical environments, this technique could allow an attacker to:

  • Container escape: Establish communication between isolated containers
  • Data exfiltration: Create covert channels to extract sensitive information
  • Lateral movement: Pivot between compromised and target containers
  • Command and control: Maintain hidden communication with compromised systems
  • Policy bypass: Circumvent network policies and security controls

The ability to create invisible cross-namespace communication channels is particularly concerning for cloud environments, Kubernetes clusters, and other multi-tenant systems where network isolation is a fundamental security boundary.
