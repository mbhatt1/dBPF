IRQ Affinity Chaos: Weaponizing Interrupt Handling

Wut

A technique that uses eBPF to manipulate interrupt request (IRQ) affinity settings, allowing attackers to create performance degradation, resource starvation, and side-channel attacks by controlling which CPU cores handle specific hardware interrupts. This undermines system stability and isolation guarantees.

Why

Because eBPF + misconfiguration => broken isolation. IRQ affinity is a critical performance tuning mechanism that determines which CPU cores handle specific hardware interrupts. By manipulating these settings through eBPF, attackers can create targeted performance degradation, enable side-channel attacks, or cause system instability while evading detection by traditional monitoring tools.

Conclusion

eBPF is all you need. The ability to manipulate IRQ affinity settings through eBPF creates a powerful primitive for performance degradation and side-channel attacks. This technique highlights why eBPF capabilities should be treated as highly privileged operations that require strict access controls, especially in environments where performance isolation is critical.

Technical Details

IRQ Handling Architecture

The Linux interrupt handling system consists of:

  • Hardware Interrupts: Signals from devices requiring CPU attention
  • Interrupt Controller: Hardware that manages interrupt delivery
  • IRQ Handlers: Kernel functions that process specific interrupts
  • SMP IRQ Affinity: Mechanism to control which CPU cores handle specific IRQs
  • /proc/irq/*/smp_affinity: Interface for viewing and setting IRQ affinity

In multi-core systems, distributing interrupts across cores is critical for performance and load balancing.

Exploitation Technique

The exploit leverages eBPF’s ability to attach to kernel functions that implement IRQ handling and affinity management. By intercepting these calls, an attacker can:

  1. Hook IRQ dispatch: Attach to functions like irq_dispatch() or handle_irq_event()
  2. Manipulate affinity settings: Modify CPU affinity masks for specific interrupts
  3. Create CPU hotspots: Force multiple high-frequency interrupts to the same core
  4. Implement side-channels: Use timing differences in interrupt handling for information leakage
  5. Maintain stealth: Make performance issues appear to be non-malicious system behavior

Detection Methods

Defenders should monitor for:

  • Unexpected eBPF programs attached to IRQ-related functions
  • Unusual patterns of IRQ distribution across CPU cores
  • Unexplained performance degradation or CPU hotspots
  • Changes to IRQ affinity settings that don’t match system configuration
  • Timing anomalies in interrupt handling

This technique demonstrates why proper eBPF restrictions are critical for maintaining performance isolation, especially in multi-tenant environments where workload interference could impact service level agreements or enable side-channel attacks.

Real-world Impact

In practical environments, this technique could allow an attacker to:

  • Degrade system performance in targeted ways
  • Create denial of service conditions for specific hardware
  • Extract sensitive information through timing side-channels
  • Interfere with real-time processing guarantees
  • Cause system instability that’s difficult to diagnose

The ability to manipulate IRQ handling at a low level creates particularly concerning scenarios in environments with strict performance requirements or where side-channel resistance is important, such as cloud computing platforms or financial systems.
