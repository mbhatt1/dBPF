Chapter 0: Field Manual Preface

The Dark Side of BPF: A Security Professional’s Field Manual

Disclaimer and Intent

This field manual documents the inherent capabilities of eBPF (extended Berkeley Packet Filter) as implemented in the Linux kernel. Every technique, method, and proof-of-concept demonstrated within these pages represents intended functionality of the eBPF subsystem, not vulnerabilities or bugs.

What This Manual Is

This is a field manual for security professionals, red team operators, and researchers who need to understand the full spectrum of eBPF capabilities. Like any powerful technology, eBPF can be wielded for both defensive and offensive purposes. This manual explores the latter—not to enable malicious activity, but to ensure defenders understand what they’re defending against.

What This Manual Is Not

This manual does not document vulnerabilities. Every technique presented here:

  • Uses eBPF exactly as designed by kernel developers
  • Leverages documented and intended kernel interfaces
  • Operates within the bounds of eBPF’s security model
  • Requires appropriate privileges (typically CAP_BPF or CAP_SYS_ADMIN)
  • Functions through legitimate kernel APIs and helper functions

The Nature of eBPF

eBPF is fundamentally a kernel programming interface. When you load an eBPF program, you are literally injecting code into the kernel that runs with kernel privileges. This is not a side effect or an unintended consequence—it is the primary design goal of eBPF.

The techniques in this manual demonstrate what happens when this legitimate, powerful capability is used with adversarial intent. They showcase the inherent tension between functionality and security that exists in any sufficiently powerful system.

Use as Intended

Every “exploit” in this manual is actually eBPF working exactly as intended:

  • Hooking kernel functions: This is the core purpose of kprobes and tracepoints
  • Modifying kernel behavior: eBPF programs are designed to influence kernel decisions
  • Accessing kernel data structures: Helper functions exist specifically for this purpose
  • Bypassing user-space restrictions: Kernel-level code naturally operates above user-space constraints

The “dark side” emerges not from bugs or oversights, but from the fundamental nature of kernel-level programmability.

The Security Paradox

eBPF presents a fascinating security paradox:

  1. By design, eBPF provides unprecedented observability and control over kernel behavior
  2. By necessity, this requires extensive privileges and kernel access
  3. By consequence, these same capabilities can be used to subvert security mechanisms

This is not a flaw—it’s an inherent characteristic of any system that provides low-level programmability. The techniques in this manual exist because eBPF is working correctly, not because it’s broken.

Responsible Use

This manual is intended for:

  • Security researchers studying kernel security models
  • Red team operators conducting authorized penetration testing
  • Blue team defenders understanding attack techniques
  • System administrators hardening eBPF deployments
  • Kernel developers considering security implications of new features

The Defender’s Advantage

Understanding these techniques provides defenders with crucial insights:

  • Detection strategies: Knowing how attacks work enables better monitoring
  • Hardening approaches: Understanding capabilities informs restriction policies
  • Risk assessment: Realistic evaluation of eBPF deployment security
  • Incident response: Recognizing eBPF-based attacks in the wild

A Note on Ethics

The techniques documented here should only be used in authorized environments with explicit permission. The goal is education and defense, not exploitation. As with any powerful tool, the responsibility lies with the wielder, not the tool itself.

Moving Forward

As you progress through this field manual, remember that you’re not learning about broken software—you’re learning about the intended capabilities of one of the most powerful kernel technologies ever developed. The “dark side” exists because the “light side” is so incredibly bright.

eBPF is not vulnerable. eBPF is powerful. This manual teaches you to understand the difference.

“Any sufficiently advanced technology is indistinguishable from magic. Any sufficiently powerful technology can be used for both creation and destruction.”
