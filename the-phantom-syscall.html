The Phantom Syscall: Bypassing Seccomp Filters with eBPF

Wut

Leveraging permitted syscalls plus eBPF helpers to make the kernel perform forbidden operations while seccomp remains oblivious. This technique allows attackers to execute operations that should be blocked by seccomp filters, creating “phantom” syscalls that bypass security controls.

Why

Because eBPF + misconfiguration => broken isolation. Seccomp filters are widely used to restrict which syscalls a process can make, providing an important security boundary. However, eBPF programs can use kernel helper functions to perform operations that would normally require syscalls, effectively bypassing seccomp restrictions.

Technical Details

Seccomp Architecture

Seccomp (secure computing mode) is a Linux kernel feature that restricts the syscalls a process can make. It operates by:

  • Filtering syscalls based on syscall number and arguments
  • Allowing, blocking, or logging attempted syscalls
  • Providing a security boundary for containerized applications

In container environments, seccomp profiles are often used to restrict containers to a limited set of syscalls, reducing the attack surface.

    switch (syscall_nr) {
        case SYS_read: return "read";
        case SYS_write: return "write";
        case SYS_open: return "open";
        case SYS_close: return "close";
        // ... (truncated for brevity)

    }
}

        printf("  Path: %s\n", e->path);

// Create a trigger file descriptor
int create_trigger_fd() {
    // Create a pipe
    int pipefd[2];
    if (pipe(pipefd) < 0) {
        perror("pipe");
        return -1;
    }
    
    // Close the write end
    close(pipefd[1]);
    
    // Duplicate the read end to our trigger FD
    int trigger_fd = fcntl(pipefd[0], F_DUPFD, 42);
    if (trigger_fd < 0) {
        perror("fcntl");
        close(pipefd[0]);
        return -1;
    }
    
    // Close the original read end
    close(pipefd[0]);
    
    return trigger_fd;
}
