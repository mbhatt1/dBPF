# ch06 Silence SELinux — LSM SYNTHETIC variant

Sibling POC to `ch06-silence-selinux-lsm/` (the "real" BPF LSM override
that needs a SELinux-enforcing kernel with `lsm=bpf,selinux`). On hosts
that lack SELinux — Docker Desktop's linuxkit 6.12 aarch64 is the
canonical example — there is no organic `avc_has_perm` deny for a classic
`fmod_ret` program to flip, so the primitive cannot be demonstrated end
to end. This variant closes that gap by *synthesizing* the deny inside
BPF itself, then flipping it, using a single sleepable LSM program on
`file_open` driven by a control map.

Marked clearly as a variant: it does NOT exercise SELinux and does NOT
prove anything about SELinux. It proves the LSM fmod_ret primitive
("return-value replacement at the LSM hook") on a SELinux-less host.

## Mechanism

A single `SEC("lsm.s/file_open")` sleepable program reads a per-CPU
control struct from `ctrl_map` to select its stage at runtime:

| Stage | Behaviour |
|-------|-----------|
| `STAGE_OFF`  | pass-through; program returns 0 |
| `STAGE_DENY` | DENIER: returns `-EACCES` for `(target_uid, sentinel_path)` |
| `STAGE_FLIP` | FLIPPER: same match, returns 0 — turns a would-be deny into allow |

Stages are toggled from userspace via signals to the loader:
`SIGUSR1` → DENY, `SIGUSR2` → FLIP, `SIGHUP` → OFF. Sentinel matching
uses `bpf_d_path()` on `file->f_path`, which is why the program must be
sleepable.

Using a single program with a map-driven toggle (rather than a
standalone "denier" plus a "flipper") sidesteps LSM fmod_ret chaining
semantics: a non-zero return from the first program short-circuits the
hook chain, which would stop a second program from ever running on the
same hook.

## Hook(s)

- `lsm.s/file_open` — sleepable BPF LSM program, `fmod_ret`.

## Host prereqs

- Kernel built with `CONFIG_BPF_LSM=y`.
- `cat /sys/kernel/security/lsm` must list `bpf`.
- CAP_SYS_ADMIN (LSM fmod_ret requires full sysadmin).
- Does NOT require SELinux.

## Build / Run

```
cd pocs/ch06-silence-selinux-lsm-synthetic && make
sudo ./build/ch06-silence-selinux-lsm-synthetic -u <uid> -s <sentinel>
sudo bash trigger.sh
```

## Evidence

Per-event loader lines:
```
[ch06-synth] stage=deny pid=... uid=... verdict=-13 path=/tmp/.../sentinel.txt
[ch06-synth] stage=flip pid=... uid=... verdict=0  path=/tmp/.../sentinel.txt
```

Trigger verdict line:
```
=== CH06_CONCEPT_PROVEN denial_injected=yes flip_applied=yes ===
```

On missing BPF LSM, both loader and trigger emit
`CH06_SYNTH_SKIP reason="..."` and exit 0 (honest-skip).

## Limitations

- Not a SELinux exploit. The deny is synthesized by the BPF program, not
  generated by SELinux's AVC. Use `ch06-silence-selinux-lsm/` on a real
  SELinux host to flip organic AVC denials.
- Flipping still requires CAP_SYS_ADMIN, same as any LSM fmod_ret.
- `lsm.s/file_open` fires on every open(2); the match filter
  (target_uid + sentinel-path prefix) keeps noise low but is the only
  thing between "targeted deny" and "system-wide chaos".
