# Ch06 -- Silencing SELinux (LSM synthetic variant)

**Category**: ANALOG
**Primitive**: LSM fmod_ret on `file_open` with map-driven deny/flip stages
**Hook(s)**: `SEC("lsm.s/file_open")`
**Architecture**: aarch64 + x86_64

## What this demonstrates

On hosts that lack SELinux, proves the LSM fmod_ret primitive ("return-value replacement at the LSM hook") by synthesizing a deny inside BPF itself, then flipping it. A single sleepable LSM program on `file_open` implements both the denier and the flipper, selected at runtime via a `ctrl_map` stage control toggled by signals (SIGUSR1=deny, SIGUSR2=flip, SIGHUP=off).

## What this does NOT do

Does not exercise SELinux and does not prove anything about SELinux. The deny is synthesized by the BPF program, not generated by SELinux's AVC. Use `ch06-silence-selinux-lsm/` on a real SELinux host to flip organic AVC denials. `lsm.s/file_open` fires on every `open(2)`.

## Prerequisites

- `CONFIG_BPF_LSM=y`
- `cat /sys/kernel/security/lsm` must list `bpf`
- `CAP_SYS_ADMIN`
- Does NOT require SELinux

## Files

| File | Purpose |
|------|---------|
| `ch06-silence-selinux-lsm-synthetic.bpf.c` | Kernel-side BPF LSM program (fmod_ret on file_open, map-driven stages) |
| `ch06-silence-selinux-lsm-synthetic.c` | Userspace loader with signal-based stage control |
| `trigger.sh` | Activity generator (three-phase: baseline, deny, flip) |
| `Makefile` | Build (uses shared/common.mk) |

## Build & Run

```bash
# Inside the harness container:
make
sudo ./build/ch06-silence-selinux-lsm-synthetic -u <uid> -s <sentinel>
# In another terminal:
bash trigger.sh
```

## Detection

- `bpftool prog list type lsm` shows the attached sleepable program on `file_open`.
- Unexpected `-EACCES` on file opens for specific UIDs/paths while the filesystem is healthy.
- `bpf()` syscall audit records program load.
