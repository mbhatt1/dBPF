Powercap Override: Manipulating System Power Management

Wut

A technique using eBPF to intercept and manipulate the Linux kernel’s power capping framework, allowing attackers to override power limits, thermal controls, and energy monitoring. This attack can cause denial of service, hardware damage, or enable side-channel attacks by manipulating the power states of critical system components.

Why

Because eBPF + misconfiguration => broken isolation. Modern systems rely on power capping mechanisms like Intel’s RAPL (Running Average Power Limit) to maintain safe operation and prevent thermal damage. By using eBPF to intercept and modify these power management operations, attackers can bypass hardware safety limits, cause denial of service through power throttling, or create side channels for data exfiltration.

Attacker hat on

  1. Identify a target system with eBPF capabilities and power management features
  2. Map the kernel functions responsible for power capping and thermal control
  3. Develop eBPF programs that hook into these power management functions
  4. Load the malicious BPF programs with appropriate privileges
  5. Intercept and modify power limit values during runtime
  6. Manipulate power states to create side channels or cause denial of service
  7. Exfiltrate data through power consumption patterns or degrade system performance

Defender hat on

  1. Remove CAP_BPF from untrusted processes and containers
  2. Implement BPF LSM policies to restrict eBPF program loading
  3. Monitor for unexpected eBPF programs attached to power management functions
  4. Implement hardware-level power monitoring independent of the OS
  5. Set up external thermal monitoring for critical systems
  6. Consider physical isolation for sensitive workloads

Conclusion

eBPF is all you need. The ability to manipulate power management through eBPF creates dangerous scenarios ranging from hardware damage to sophisticated side-channel attacks. This technique highlights why eBPF capabilities should be treated as highly privileged operations that require strict access controls, especially in environments where power management is critical for security or reliability.

Technical Details

Power Capping Architecture

The Linux kernel’s power capping framework provides:

  • RAPL (Running Average Power Limit): Intel’s technology for monitoring and controlling power consumption
  • Power Zones: Separate control for CPU, DRAM, GPU, and package power domains
  • Thermal Controls: Mechanisms to prevent overheating through power limiting
  • Energy Accounting: Precise measurement of energy consumption by different components

These mechanisms are exposed through kernel interfaces and the sysfs filesystem under /sys/class/powercap/.

Exploitation Technique

The exploit leverages eBPF’s ability to attach to kernel functions that implement power management. By intercepting these calls, an attacker can:

  1. Hook power limit functions: Attach to functions like rapl_write_power_limit() or powercap_register_zone()
  2. Modify power constraints: Change maximum and minimum power limits for components
  3. Bypass thermal throttling: Prevent the system from throttling under high temperatures
  4. Create power side channels: Manipulate power states to leak information
  5. Cause performance degradation: Artificially limit power to critical components

// Simplified eBPF program to manipulate power limits
SEC("kprobe/rapl_write_power_limit")
int BPF_KPROBE(hook_power_limit, struct powercap_zone *zone,
               u64 power_limit, int constraint_index)
{
    // Get zone information
    char name[ZONE_NAME_LEN];
    bpf_probe_read_str(name, sizeof(name), zone->name);
    
    // Check if this is a target zone (e.g., CPU package)
    if (bpf_strncmp(name, "package", sizeof("package")) == 0) {
        // For CPU package power, manipulate the limit
        // This could be to increase it beyond safe levels
        // or decrease it to cause throttling
        u64 modified_limit;
        
        if (is_attack_mode(ATTACK_THERMAL_STRESS)) {
            // Remove power limits to cause thermal stress
            modified_limit = 0xFFFFFFFFFFFFFFFF; // Effectively unlimited
        } else if (is_attack_mode(ATTACK_THROTTLE)) {
            // Set very low power limit to cause throttling
            modified_limit = power_limit / 4;
        } else if (is_attack_mode(ATTACK_SIDE_CHANNEL)) {
            // Manipulate power limit based on sensitive data
            modified_limit = create_side_channel_limit(power_limit);
        }
        
        // Override the power limit value
        bpf_probe_write_user(&power_limit, &modified_limit, sizeof(modified_limit));
    }
    
    return 0;
}

// Hook energy consumption reading for side channels
SEC("kprobe/rapl_read_energy")
int BPF_KPROBE(hook_energy_read, struct powercap_zone *zone, u64 *energy)
{
    // Get process information
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    
    // Check if this is a process we want to monitor
    if (is_target_process(pid)) {
        // Store the energy reading for side channel analysis
        u32 key = 0;
        bpf_map_update_elem(&energy_readings, &key, energy, BPF_ANY);
    }
    
    return 0;
}

Detection Methods

Defenders should monitor for:

  • Unexpected eBPF programs attached to power management functions
  • Discrepancies between configured power limits and actual power consumption
  • Unusual thermal patterns or unexpected throttling behavior
  • Unexpected changes to power management configuration
  • System instability or performance issues correlated with power management changes

This technique demonstrates why proper eBPF restrictions are critical for maintaining system integrity and security, especially in environments where power management is important for reliability or where side-channel attacks are a concern.

Real-world Impact

In practical environments, this technique could allow an attacker to:

  • Hardware damage: Override thermal protections leading to physical damage
  • Denial of service: Cause system throttling or instability through power manipulation
  • Data exfiltration: Create power-based side channels to leak sensitive information
  • Energy consumption attacks: Increase power costs in data centers
  • Reliability degradation: Cause intermittent failures through thermal stress

The ability to manipulate power management creates particularly concerning scenarios for data centers, cloud environments, and critical infrastructure where system reliability and energy efficiency are essential.
